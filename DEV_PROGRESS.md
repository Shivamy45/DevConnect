## Architecture Decisions
- Using Express 5 promise-based error handling (no asyncHandler wrappers; rejected promises reach global error middleware).
- Services throw ApiError for business errors; unexpected errors bubble automatically.
- Public IDs (not Mongo ObjectIds) are exposed externally.
- Refresh tokens are stored hashed in embedded user sessions.
- Default avatars are uploaded to Cloudinary.
- Multi-device refresh token support.
- High-growth data is stored in separate collections.

### Development Workflow
- Architecture, business rules, APIs, database design, validation rules, authorization, and feature planning are always designed before implementation.
- AI is used as an implementation accelerator for repetitive backend work after the design is finalized.
- AI may generate models, controllers, services, routes, validation schemas, CRUD logic, DTOs, and boilerplate tests.
- Every AI-generated change must be reviewed for architecture, security, performance, validation, authorization, error handling, query efficiency, consistency, and code quality.
- Avoid unnecessary abstractions, helper utilities, duplicate logic, dead code, premature optimization, and any code that does not fit the existing architecture.
- For each new feature, decide first whether it should be implemented manually (new concepts or learning-critical work) or generated by AI (well-understood, repetitive implementation).
- Before any AI implementation, finalize the feature design and prepare a constrained implementation prompt that requires the generated code to follow the project's existing architecture and conventions without introducing unrelated changes.
